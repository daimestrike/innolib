# API

У системы есть простой REST API. На нём работает сам интерфейс, и им же можно пользоваться из своих скриптов: выгрузить реестр в отчёт, завести кейсы из другой системы, встроить консультанта в бота.

Все запросы и ответы в формате JSON (UTF-8). Если приложение опубликовано под префиксом, например `/innolib/`, он добавляется перед путём: `https://portal.company.local/innolib/api/cases`.

Ошибки возвращаются в едином формате:
```json
{"error": "код_ошибки", "message": "Понятное описание на русском"}
```

## Служебное

### `GET /healthz`
Проверка живости для мониторинга.
```json
{"ok": true, "version": "1.2.1", "cases": 42}
```

### `GET /api/config`
Что включено на сервере. Интерфейс по этому ответу решает, показывать ли предупреждения.
```json
{
  "version": "1.2.1",
  "llm": true,
  "chatModel": "model-small",
  "embeddings": false,
  "stages": ["idea", "research", "pilot", "launched", "stopped"],
  "directions": ["GenAI", "Компьютерное зрение", "OCR/VLM", "Антифрод", "Аналитика и прогнозы", "Автоматизация процессов"],
  "canDelete": false
}
```

## Кейсы

### `GET /api/cases`
Все кейсы, от недавно изменённых к старым.
```json
{"cases": [
  {
    "id": "6c2499307c84",
    "code": "INN-009",
    "title": "Голосовой помощник директора магазина",
    "type": "idea",
    "stage": "idea",
    "direction": "GenAI",
    "problem": "Директор тратит много времени на поиск отчётов и регламентов.",
    "solution": "Голосовой ассистент отвечает на вопросы о показателях магазина и регламентах.",
    "effect": "",
    "effectKind": "plan",
    "unit": "Магазины / Операции",
    "owner": "",
    "tags": ["голос", "ассистент", "директор", "отчёты"],
    "wiki": "",
    "createdAt": "2026-09-24T10:00:00Z",
    "updatedAt": "2026-09-24T10:00:00Z"
  }
]}
```

Значения `stage`: `idea` (Идея), `research` (Проработка), `pilot` (Пилот), `launched` (Внедрено), `stopped` (Остановлено). `type`: `project` или `idea`. `effectKind`: `plan` или `fact`.

### `POST /api/cases`
Создать кейс. Код назначит сервер. Обязательно только `title`, остальные поля по желанию. Стадию и тип можно передавать и по-русски (`"пилот"`, `"идея"`), сервер нормализует значения.
```bash
curl -X POST http://localhost:8080/api/cases \
  -H 'Content-Type: application/json' \
  -d '{"title": "Распознавание ценников по фото", "stage": "пилот", "direction": "Компьютерное зрение", "tags": "ценники, фото"}'
```
Ответ: `201` и созданная карточка целиком.

### `PATCH /api/cases/{id}`
Изменить поля. Передаются только те, что меняются.
```bash
curl -X PATCH http://localhost:8080/api/cases/6c2499307c84 \
  -H 'Content-Type: application/json' \
  -d '{"stage": "pilot", "effect": "−20 % времени на поиск отчётов"}'
```

### `DELETE /api/cases/{id}`
Удалить кейс. Работает, только если на сервере задан `ADMIN_TOKEN`.
```bash
curl -X DELETE http://localhost:8080/api/cases/6c2499307c84 -H 'X-Admin-Token: <токен>'
```

### `GET /api/export.csv`, `GET /api/export.json`
Выгрузка реестра файлом. CSV — с разделителем `;` и BOM, открывается в Excel. JSON — формат резервной копии, его принимает команда `import`.

## Мастер карточки

### `POST /api/parse`
Разобрать свободный текст в поля карточки с помощью модели. Все поля запроса необязательны, но хотя бы одно должно быть заполнено.
```json
{
  "what": "Сделали бота, который отвечает директорам магазинов про выручку",
  "problem": "Директора тратят время на поиск отчётов",
  "stage": "Пилот. 10 магазинов",
  "effect": "−30 % времени на поиск",
  "wikiText": "…текст страницы вики…",
  "chat": "…диалог с консультантом…",
  "allowFollowup": true
}
```
Ответ — черновик карточки:
```json
{
  "title": "Бот для директоров магазинов",
  "type": "project", "stage": "pilot", "direction": "GenAI",
  "problem": "…", "solution": "…", "effect": "−30 % времени на поиск", "effectKind": "plan",
  "unit": "", "owner": "", "tags": ["бот", "директор"],
  "missing": [],
  "followup": null
}
```
`missing` — каких сведений не хватило (`problem`, `stage`, `effect`). `followup` — уточняющий вопрос или `null`. Черновик **не сохраняется**: чтобы завести кейс, отправьте его в `POST /api/cases`.

Если модель не настроена — `503 llm_disabled`.

## Консультант

### `POST /api/chat`
Вопрос консультанту. В запросе передаётся весь диалог, последнее сообщение должно быть от пользователя. Сервер сам не хранит историю.
```json
{"messages": [
  {"role": "user", "content": "Что у нас есть по антифроду?"},
  {"role": "assistant", "content": "…"},
  {"role": "user", "content": "А что из этого можно масштабировать?"}
]}
```

Ответ приходит потоком **Server-Sent Events** (`Content-Type: text/event-stream`). Каждое событие — строка `data: {json}`:
```
data: {"type": "sources", "sources": [{"ref": "INN-002", "kind": "case", "title": "Антифрод на кассах самообслуживания", "stage": "pilot", "caseId": "…", "snippet": "…"}]}

data: {"type": "delta", "text": "В реестре два проекта по антифроду: "}

data: {"type": "delta", "text": "[INN-002] и [INN-010]…"}

data: {"type": "done"}
```
При ошибке модели приходит `{"type": "error", "code": "llm_auth", "message": "…"}`.

Пример чтения потока из Python:
```python
import json, urllib.request
req = urllib.request.Request(
    "http://localhost:8080/api/chat",
    data=json.dumps({"messages": [{"role": "user", "content": "Что есть по CV?"}]}).encode(),
    headers={"Content-Type": "application/json"})
with urllib.request.urlopen(req) as r:
    for line in r:
        line = line.decode().strip()
        if line.startswith("data:"):
            ev = json.loads(line[5:])
            if ev["type"] == "delta":
                print(ev["text"], end="", flush=True)
```

Если модель не настроена, консультант всё равно отвечает: присылает найденные источники и сообщение о том, что модель не подключена.

### `GET /api/search?q=…`
Тот же поиск, что использует консультант, но без модели. Полезен для отладки: видно, какие фрагменты попадут в контекст.
```bash
curl -G http://localhost:8080/api/search --data-urlencode "q=потери на кассах"
```
```json
{"results": [
  {"ref": "INN-002", "kind": "case", "title": "Антифрод на кассах самообслуживания", "score": 0.03279, "text": "[INN-002] …"}
]}
```

## Генератор идей

### `POST /api/ideas`
```json
{
  "topic": "Списания свежей продукции",
  "direction": "Компьютерное зрение",
  "count": 4,
  "exclude": ["Умные ценники со сроком годности"]
}
```
`topic` обязателен. `direction` необязателен. `count` — от 1 до 6, по умолчанию 3. `exclude` — названия идей, которые не нужно повторять.

Ответ:
```json
{"ideas": [
  {
    "title": "Камера над витриной фреша",
    "problem": "Пустые полки и просрочка на витрине",
    "solution": "CV-модель на существующих камерах видит пустоты и просрочку и отправляет задачу сотруднику.",
    "direction": "Компьютерное зрение",
    "effect": "Меньше out-of-stock, метрика — доля пустых полок",
    "firstStep": "Разметить 500 кадров из одного магазина",
    "novelty": "Переиспользует модель распознавания ценников",
    "basedOn": ["INN-004", "INN-008"]
  }
]}
```
В `basedOn` сервер оставляет только коды, которые есть в реестре. Идеи **не сохраняются**. Чтобы завести идею, отправьте её в `POST /api/cases`.

Если модель не настроена — `503 llm_disabled`.

## База знаний

### `GET /api/docs`
Список документов без текста.
```json
{"docs": [{"id": 1, "code": "DOC-1", "title": "Регламент пилотов", "filename": "Регламент пилотов.docx", "chars": 5230, "createdAt": "2026-09-29T06:36:00Z"}]}
```

### `POST /api/docs`
Добавить документ. Два варианта тела запроса.

Файл в base64 (TXT, MD, CSV, HTML, DOCX):
```json
{"filename": "Регламент пилотов.docx", "contentBase64": "UEsDBBQABgAI…"}
```
Готовый текст:
```json
{"title": "Критерии масштабирования", "text": "Пилот переходит во внедрение, если…"}
```
Ответ: `201` и описание документа. Ограничение на размер запроса — 25 МБ. Неподдерживаемый формат или пустой документ — `400 bad_document` с объяснением.

### `DELETE /api/docs/{id}`
Удалить документ. Нужен заголовок `X-Admin-Token`.

## Коды ошибок

| HTTP | `error` | Когда |
|---|---|---|
| 400 | `bad_request` | Некорректный JSON или не хватает обязательных полей |
| 400 | `bad_document` | Документ не удалось прочитать |
| 403 | `forbidden` | Удаление без правильного `X-Admin-Token` |
| 404 | `not_found` | Нет такого адреса, кейса или документа |
| 502 | `llm_auth` | Шлюз не принял ключ |
| 502 | `llm_unreachable` | Шлюз недоступен по сети или не ответил вовремя |
| 502 | `llm_not_found` | Неверный адрес API или модель |
| 502 | `llm_rate_limited` | Слишком много запросов к шлюзу |
| 502 | `llm_http` | Шлюз вернул другую ошибку HTTP (текст ошибки — в `message`) |
| 502 | `llm_bad_response` | Модель ответила не в ожидаемом формате |
| 503 | `llm_disabled` | Модель не настроена на сервере |

## Командная строка

Помимо HTTP API у приложения есть команды для администратора:

| Команда | Что делает |
|---|---|
| `python3 app.py` | Запустить веб-сервер |
| `python3 app.py import файл.csv` | Загрузить кейсы из CSV или JSON |
| `python3 app.py export > backup.json` | Выгрузить реестр в JSON |
| `python3 app.py add-doc файл.docx …` | Добавить документы в базу знаний |
| `python3 app.py check-llm` | Проверить подключение к модели |
| `python3 app.py reindex` | Пересчитать векторы для гибридного поиска (если задан `EMBED_MODEL`) |
