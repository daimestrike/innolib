# Данные и наполнение реестра

Реестр полезен ровно настолько, насколько хорошо он заполнен. В этом документе описано, из чего состоит карточка, как её правильно заполнять, как перенести существующие проекты из Excel и что положить в базу знаний.

## Карточка кейса

| Поле | Обязательно | Что писать | Пример |
|---|---|---|---|
| **Код** | назначается сам | `INN-` и порядковый номер. Не меняется, по нему на кейс ссылаются консультант и коллеги | `INN-007` |
| **Название** | да | Коротко и по сути, до 60 символов. Из названия должно быть понятно, что это | «Прогноз списаний свежей продукции» |
| **Тип** | да | **Проект**, если по нему уже идёт работа. **Идея**, если это пока предложение | Проект |
| **Стадия** | да | Идея, Проработка, Пилот, Внедрено, Остановлено | Внедрено |
| **Направление** | да | Одно из шести, см. ниже | Аналитика и прогнозы |
| **Проблема** | желательно | Чья это боль и в чём она. Одно-два предложения | «Высокие списания фреша из-за неточного заказа» |
| **Решение** | желательно | Что сделали или предлагают сделать | «Модель прогнозирует спрос по магазину и дню и корректирует автозаказ» |
| **Эффект** | желательно | Результат, лучше в цифрах | «−12 % списаний фреша» |
| **План / факт** | да | План — ожидаемый эффект. Факт — измеренный | Факт |
| **Подразделение** | желательно | Бизнес-заказчик | Цепочка поставок |
| **Владелец** | желательно | Кто ведёт проект: человек или команда. К нему пойдут с вопросами | Команда аналитики |
| **Теги** | нет | До 8 коротких слов для поиска | прогноз, спрос, списания |
| **Ссылка на вики** | нет | Страница с подробностями | — |

### Направления

| Направление | Что туда относится |
|---|---|
| GenAI | Чат-боты, ассистенты, генерация текстов и контента, аватары |
| Компьютерное зрение | Распознавание по фото и видео: полки, ценники, кассы, очереди |
| OCR/VLM | Распознавание документов: накладные, договоры, сканы |
| Антифрод | Выявление мошенничества, хищений, аномалий |
| Аналитика и прогнозы | Прогнозирование спроса, оптимизация, отчётность |
| Автоматизация процессов | IoT, удалённые проверки, роботизация рутинных операций |

Список направлений можно поменять под себя (см. [Как это устроено](03-arhitektura.md#куда-расти)).

### Как понять, какая стадия

Самый частый вопрос при заполнении. Простое правило:
- **Идея**: денег и людей на это пока не выделено.
- **Проработка**: кто-то уже тратит на это время. Считают экономику, выбирают решение, согласуют.
- **Пилот**: решение работает на реальных данных, но в ограниченном масштабе.
- **Внедрено**: работает в продуктиве и приносит эффект без ручной поддержки команды проекта.
- **Остановлено**: работу прекратили. В описании эффекта стоит написать почему, например «низкая точность на старых камерах». Это самые ценные для других кейсы.

### Хорошая и плохая карточка

**Плохо:**
> **Название:** Бот
> **Решение:** Сделали бота
> **Эффект:** Хороший

Такую карточку не найти поиском, консультант не сможет о ней рассказать, а коллега не поймёт, стоит ли писать владельцу.

**Хорошо:**
> **Название:** ИИ-ассистент для службы поддержки магазинов
> **Проблема:** Типовые обращения магазинов перегружают первую линию поддержки.
> **Решение:** Бот отвечает на типовые вопросы по базе знаний и заводит заявку, если не справился.
> **Эффект (факт):** 35 % обращений закрываются без оператора.
> **Подразделение:** ИТ-поддержка · **Владелец:** Команда поддержки
> **Теги:** бот, поддержка, база знаний, заявки

## Первичное наполнение из Excel

Если проекты уже ведутся в таблице, их удобнее загрузить разом, чем заводить по одному.

### 1. Подготовить таблицу

Возьмите шаблон `data/import_template.csv` из репозитория и откройте его в Excel. Колонки:

```
title; type; stage; direction; owner; unit; problem; solution; effect; effectKind; tags; wiki
```

Что важно знать:
- **title** — единственная обязательная колонка. Строки без названия пропускаются.
- **type**: `проект` или `идея` (можно `project` / `idea`).
- **stage**: `идея`, `проработка`, `пилот`, `внедрено`, `остановлено`. Английские значения (`idea`, `research`, `pilot`, `launched`, `stopped`) тоже подходят. Неизвестное значение превратится в «Идею».
- **direction**: одно из шести направлений, написанное как в таблице выше.
- **effectKind**: `план` или `факт`.
- **tags**: через точку с запятой, например `прогноз; спрос; списания`.
- Если в таблице есть колонки `createdAt` / `updatedAt` в формате `2026-06-18T10:00:00Z`, даты сохранятся. Если нет, будет стоять дата импорта.

Лишние колонки игнорируются, так что можно выгрузить свою таблицу и просто переименовать нужные заголовки.

### 2. Сохранить как CSV

В Excel: «Файл → Сохранить как → CSV UTF-8 (разделитель — запятая)». Разделитель может быть `;`, `,` или табуляция, система определит его сама. Главное — кодировка UTF-8, иначе кириллица испортится.

### 3. Загрузить

```bash
python3 app.py import cases.csv
# Загружено кейсов: 42. Всего в реестре: 42
```

В Docker файл сначала нужно положить в контейнер:
```bash
docker cp cases.csv innolib:/data/cases.csv
docker compose exec innolib python3 app.py import /data/cases.csv
```

Импорт добавляет кейсы, а не заменяет существующие. При повторном запуске того же файла появятся дубли. Поэтому сначала проверьте файл на небольшом куске.

Импорт из JSON работает так же: `python3 app.py import backup.json`. Формат — тот, что отдаёт «Резервная копия JSON». Коды кейсов (`INN-…`) при этом сохраняются, поэтому ссылки на кейсы в переписке и документах не ломаются. Если код уже занят, кейс получит следующий свободный. Колонку `code` можно указать и в CSV.

### 4. Проверить

Откройте реестр, посмотрите на воронку и пролистайте несколько карточек. Особенно проверьте стадии: если все кейсы оказались в «Идее», скорее всего, в колонке `stage` значения написаны не так, как ожидает система.

## Как поддерживать реестр живым

Реестр умирает, если его обновляют раз в квартал к отчёту. Несколько практик, которые помогают:

- **Назначьте хозяина реестра.** Один человек раз в неделю смотрит новые карточки, правит названия и направления, склеивает дубли.
- **Стадия меняется сразу.** Пилот стартовал — владелец в тот же день переводит карточку в «Пилот». Это один клик в карточке.
- **Факт вместо плана.** Когда эффект измерен, поменяйте «план» на «факт» и впишите цифру.
- **Не удаляйте остановленное.** Переводите в «Остановлено» и пишите причину. Для тех, кто придёт с похожей идеей, это ценнее любого успешного кейса.
- **Предлагайте заводить через консультанта.** Людям проще поговорить, чем заполнять форму. Кнопка «Оформить идею в карточку» превращает разговор в запись.

## База знаний

Кейсы отвечают на вопрос «что делали». Документы базы знаний отвечают на вопрос «как у нас принято». Консультант и генератор учитывают и то и другое.

### Что загружать

| Тип документа | Зачем |
|---|---|
| Стратегия и приоритеты | Консультант будет оценивать идеи с оглядкой на приоритеты компании |
| Регламент запуска пилота | Ответит, кто согласует, какие документы нужны, сколько длится пилот |
| Методика расчёта эффекта | Поможет правильно сформулировать метрики |
| Критерии масштабирования | Ответит, что нужно, чтобы пилот перешёл во внедрение |
| Выгрузки страниц вики по крупным проектам | Подробности, которые не помещаются в карточку |

### Как загружать

- **Из интерфейса:** вкладка «Консультант» → «Добавить документ». Можно выбрать несколько файлов сразу.
- **Из командной строки:** `python3 app.py add-doc файл1.docx файл2.md` — удобно для первичной загрузки пачки файлов.

Форматы: TXT, MD, CSV, HTML, DOCX. PDF пока не поддерживается, его нужно пересохранить в DOCX.

### Как готовить документы

- **Один документ — одна тема.** Лучше пять коротких регламентов, чем один на сто страниц.
- **Используйте заголовки.** Система режет текст по абзацам, и заголовки помогают фрагментам оставаться осмысленными.
- **Уберите служебное:** оглавления, листы согласования, колонтитулы.
- **Название файла становится названием документа**, поэтому называйте файлы по-человечески: «Регламент запуска пилотов.docx», а не «Doc_final_v3.docx».

Обновить документ можно так: администратор удаляет старую версию через API, затем загружается новая.

## Демо-данные

При первом запуске с `SEED_DEMO=1` в пустую базу загружаются 16 демонстрационных кейсов: аватар для обучения, антифрод на КСО, распознавание ТТН и УПД, прогноз списаний и другие. Они нужны, чтобы показать систему, и не описывают реальные проекты. Для боевого запуска ставьте `SEED_DEMO=0`.
